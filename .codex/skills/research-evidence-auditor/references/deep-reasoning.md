# 计算复核与冲突归因

遇到派生量、数值冲突或比较性主张时必须读取本文件。完成这里的检查后再给出 `supported`、`refuted`、`contested` 或 `insufficient`。

## 1. 派生量独立复算

不要把“证据原文与回答写了同一个百分比”当作计算正确。识别计算类型并使用原始操作数重新计算：

- 达成率：`实测值 ÷ 标称值 × 100%`
- 增长率：`(本期值 - 基期值) ÷ 基期值 × 100%`
- 百分点差：`本期百分比 - 基期百分比`
- 金额换算：`原币金额 × 汇率`
- 隐含参数：`报告结果 ÷ 原始值`

报告必须写出公式、输入、未取整结果、取整规则、复算结果与原文结果的差。操作数或规则缺失时，明确记录计算缺口。

示例：证据同时给出实测续航 612 km、标称续航 660 km 和达成率 92.7%。必须独立计算：

```text
612 ÷ 660 × 100 = 92.727272...%，四舍五入到 1 位小数为 92.7%
```

复算一致后才可确认达成率计算正确。优先调用：

```bash
python scripts/verify_calculation.py '{"operation":"ratio","values":{"numerator":"612","denominator":"660"},"scale":"100","precision":1}'
```

## 2. 数值冲突的机制归因

按数据生成链逐层回溯，不只描述“相差多少”：

```text
原始值 → 单位或币种 → 换算参数 → 公式与分母 → 取整顺序 → 报告结果
```

逐项检查：

1. 原始值是否抄错、错列或错配实体。
2. 单位是否一致，例如元/万元、ms/s、km/m、百分比/百分点。
3. 汇率、税率、折扣率或权重是否采用证据指定值。
4. 分母是否正确，是否把目标值、基期值或总样本混用。
5. 正负号和比较方向是否反转。
6. 是先逐项取整再求和，还是先汇总再取整。
7. 时间、版本、样本和统计口径是否可比。

示例：证据给出 125 万美元和汇率 7.20，报告写 860 万元人民币。

```text
期望值 = 125 × 7.20 = 900 万元
报告值 = 860 万元
隐含汇率 = 860 ÷ 125 = 6.88
```

若证据明确要求使用 7.20，可将“未按指定汇率折算”标为计算支持的根因；只有在材料说明实际用了 6.88 时，才能说“采用了 6.88 汇率”为证据确认的根因。否则把具体错误汇率保留为待验证假设。

## 3. 比较性主张分层判定

按以下顺序判定，不要因为保守原则而忽略直接证据：

1. **原文直接陈述**：来源明确写出与主张相同的比较关系，主体、指标、范围、时间和方向一致时，标记 `supported`。即使缺少两侧操作数，也只增加“无法独立复算”的计算缺口，不自动改为 `insufficient`。
2. **操作数可用**：来源给出两侧数值时，独立计算差值、百分点或增长率；复算一致才确认派生比较正确。
3. **原文与操作数冲突**：来源文字直接支持比较关系，但同一来源操作数复算后方向或幅度相反，标记 `contested`，同时引用文字和数值证据，指出来源内部不一致。
4. **只有背景相关**：既无直接比较陈述，也缺少足够操作数时，才标记 `insufficient`。

示例：来源直接写“培训组3个月留存率比未参训组高7个百分点”，但没有给出两组原始比例。该比较主张按直接陈述标记 `supported`，并记录无法独立复算的缺口。若另有数据 89% 与 82%，则复算 `89% - 82% = 7 个百分点` 并确认一致。

## 4. 根因证据等级

每条根因使用以下一个标签，避免把猜测包装成事实：

- `evidence_confirmed`：来源明确说明导致差异的机制。
- `calculation_supported`：给定数值和公式能够唯一或高度确定地推出机制错误。
- `hypothesis`：存在多个可能原因，需要补充材料验证。
- `unknown`：当前证据不能支持具体根因。

冲突报告至少包含：观察到的差异、独立复算、根因标签、依据、仍需核验的参数和建议动作。
